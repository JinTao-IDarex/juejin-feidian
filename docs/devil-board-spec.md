导出图：`output/devil-board-deal/*.png`


卡牌素材：`assets/board-cards/face-<id>.png`（整张牌面）+ `art-<id>.png`（插画带），

| 毒舌榜 | 攻击性 · 精准度 · 共鸣 | `#FF5A3C` |

⚠️ **赛道色不是随手选的装饰**：它是「封面牌赛道名 / 名次 / 分数」和「详情大牌分数 / 判词 / 进度」的**唯一色源**。
2026-09-24 视觉改版时按**各赛道的封面插画**重新校准了三个（改动原因必须成对读）：

| 赛道 | 旧 → 新 | 为什么 |
|---|---|---|
| 离谱榜 | `#FF7A1A` → `#F5A524` | 插画角色身体本身就是 `#FF7A1A`，同色标题会糊在角色身上，改成琥珀拉开层次 |
| 废话榜 | `#8A9099` → `#454D57` | 插画是黑线稿，参考图的「废话榜」也几乎是黑的；浅灰在六摞里完全压不住 |
| emo 榜 | `#4A5B8C` → `#12A173` | 插画角色是青绿（`#4ECDAF`），藏蓝标题和它完全对不上 |

**动这四个十六进制之前，先看一眼 `assets/board-cards/face-<id>.png` 里对应的那张图。**
⚠️ v0.5.0 起**封面牌不再吃这四个色**（整张牌面就是一张图），它们只驱动**详情大牌**的
名次 / 分数 / 判词 / 符号、缩略进度条当前项、赛道弹窗 —— 别按封面去挑色。

**互斥规则**：候选池是共享的一份（48 条），AI 对每条同时打 6 个赛道的分，最后每条沸点**只进它得分最高的那一个榜**。
避免同一条内容霸占 6 个榜单——那会让榜单变成"重复播放"。

## 二、抓取：实测结论（这是整个功能的前提）

`scripts/_probe_range.py` 实测（2026-09-24 08:30）：

| sort_type | 翻 60 页 | 条数 | 覆盖跨度 | 耗时 |
|---|---|---|---|---|
| 300（时间序，项目现用） | 1193 条 | **1.76 天** | 43.8s |
| 200（热度序） | 1188 条 | **14.33 天** | 44.7s |

三条硬约束：

1. **日榜用 300，周榜必须用 200**。300 翻 60 页才够到 1.76 天，永远摸不到 7 天。周榜用 200（热度序），约 30 页覆盖一周。
2. **ctime 不是严格降序** —— 不能"翻到昨天 0 点就早停"，必须**整段翻完再按 ctime 过滤**。
3. **一次全量 20–45 秒、上千条** —— 榜单绝不能实时算，必须落盘 + 后台预热。

建议参数：

```
日榜：sort_type=300，翻至 ctime < 今日 00:00 或 40 页上限
周榜：sort_type=200，翻至 ctime < 7 天前或 45 页上限
```

## 三、评分流程（两段式，别让 AI 裸打分）

**第一段 · 入围（确定性，不烧 token）**
从抓到的上千条里筛出 48 条候选：
- 硬过滤：正文 ≥ 12 字；无正文的纯图/纯链接直接出局
- 热度分 = `log(1+digg)*0.6 + log(1+cmt)*0.4`，取 Top 48

**第二段 · 定名次（AI）**
- 对 48 条候选批量请求：每条返回 6 个赛道分 + 一个"赛道分"（1–10，一位小数）+ 一句判词 + 三个维度分明细
- 分块 8 条/次，约 6 次请求，20–40s
- **复用现有 `/api/roast` 那条链路**：并发队列、内存缓存、拆半重试都已现成，不要另起一套

**关键口径：热度只决定入围，不决定名次。** 掺了热度就退化成热帖榜，AI 的判断才是这个功能的灵魂。

**可复现**：结果落盘 `data/board/day-YYYY-MM-DD.json` / `week-YYYY-Www.json`，同一天重开直接读盘，不重复烧 token。
缓存 TTL：日榜 6 小时，周榜到自然周结束。

## 五、榜单宪章（硬边界，不是可选项）

AI 给真人公开发言排"最恶毒"的名次，天然会越界。四条规矩：

1. **评内容，不评人**。禁止基于作者身份、公司、职位、地域、外貌评分。
2. **不进榜**：涉政、涉黄、人身攻击、真实姓名指向的条目，直接剔除（AI 拒答即跳过，不追问、不三次重试）。
3. **可自辩**：每条带原文链接，被评的人能点进去看到出处。
4. **宁可空着**：候选不足时显示空态，不硬凑第一名。

## 六、版式：六摞牌 → 详情页 → 切牌

三层：**首页（六摞牌）** → **赛道详情页** → **逐张切牌**。

### 6.1 首页 · 六摞牌

- 一摞 = 三张同宽竖版牌**垂直堆叠**，底下两张各向下错开 9px，只露出下边缘的白边（这就是"一摞"的全部视觉）
- 最上面那张是**封面牌**：**我们自己排的卡面版式（1 : 1.4）**，从上到下五段。

  | 段 | 内容 | 数据 |
  |---|---|---|
  | `.cover-top` | 左：赛道符号 + 名次「1」；右：最高分 | **实时** |
  | `.cover-name` | 赛道名（26px Black，赛道色，居中） | **实时** |
  | `.cover-fig` | **从参考图抠出来的角色**（透明底 PNG，`contain`） | 素材，不动 |
  | `.cover-def` | 赛道定义（10px `#6B7280`，单行省略） | **实时** |
  | `.cover-go` | 胶囊入口「点击进入 →」/ 空榜「暂无上榜」 | **实时** |

  **只有形象区那张图是参考图来的，其余五个部分全是活的 DOM 节点** —— 名次 / 分数 /
  赛道名 / 定义 / 入口都跟当天榜单联动，空榜自动退化成「0 / — / 暂无上榜」。
- 底下两张是**空白牌背**（白底 + 描边），没有内容 —— 内容等进了详情页才翻

**封面牌的纵向预算**（`.cover` 是 flex 列，283 写死、形象区吃剩余）：

```
283 − (padding 12+11) − top 22 − (name 2+30) − (fig margin 4+4) − def 13 − (go 6+22)
= 157   → 形象区实际是 178 × 157（202 − padding 12×2 = 178）
```

### ⭐ 封面牌的四版演进：三次被否，别再走回头路

| 版本 | 做法 | 结果 |
|---|---|---|
| v0.4.0 | **照着重画**：AI 出插画 + 网页字体排文字 | ❌ **字体复刻不出来**（参考图赛道名是粗描边毛笔感、名次/分数是圆头粗体） |
| v0.5.0 | **从图里切 + 凑 1:1.4**：把牌面从自带外框里挖出来再补白边 | ❌ 用户：「**贴图看起来太丑了**」—— 内容相对放大 9%、原图那圈留白与柔光外框全丢 |
| v0.5.1 | **整张参考牌直接用**，让版式适配图（1 : 1.218） | ❌ 用户：「**是把角色抠出来，不是把整张图都放进去**……卡片看起来特别奇怪，不够完善」 |
| **v0.6.0（当前）** | **自有卡面版式（文字全实时）+ 只把参考图里的角色当插画抠出来贴上** | ✅ |

> ⭐ **两条教训必须一起看，缺一条就会原地打转**：
> 1. 手上有**成品图**时，"改造它去适配版式"几乎总比"让版式适配它"更难看（v0.5.0 的教训）。
> 2. **但反过来也不成立** —— 整张成品图直接当卡面同样奇怪（v0.5.1 的教训）。
>    **正解是「版式归版式、素材归素材」**：卡面永远用我们自己排的版式（文字活的、
>    和其他卡片同比例），只把图里最有价值的那部分（角色）当成插画素材抠出来贴进去。

**v0.5.1「整图当卡面」的三宗罪**（理解 v0.6.0 为什么必然是现在这样）：

| # | 问题 | 具体表现 |
|---|---|---|
| 1 | **双框** | 参考牌自带 18px 柔光描边；坐进 card 里要么再加一圈 CSS 边框变"框中框"，要么去掉边框、牌就不像一张"卡"了 |
| 2 | **假值** | 名次 / 分数 / 定义 / 入口全烤死在图里。嘴硬榜当天 0 条，封面却永远写着「1 / 8.5」 |
| 3 | **发灰** | 整图自带 249 的页边底色 + 顶部柔光暗场，和一屏纯白自绘卡片摆在一起显脏 |

#### 连带要跟着改的三处（少改一处就出无声 bug）

| 位置 | 值 |
|---|---|
| `board.css` `--cover-w/h` + `--stack-h` | `202 / 283 / 301` |
| `board.js` `COVER_W / COVER_H` | `202 / 283` |
| `scripts/make_card_faces.py` `CHAR_OUT_W/H` | `356 / 292` |

外加 `--stack-h == --cover-h + 18`。`scripts/check_extension.py` 会断言这三者一致
（含读 PNG 的 IHDR 核像素尺寸，不依赖 Pillow），**因为图被拉伸 / 发牌落位对不上
这两种错都不会抛异常，只能靠眼睛看出来**。它还额外断言
**封面牌与详情大牌必须同比例** —— 这是发牌单轴缩放成立的前提。

⚠️ **封面牌重回 1:1.4 之后，发牌动效退回单轴缩放**（`--s0` 出发 → `--s` 落位），
v0.5.1 那套分轴 `--s0x/--s0y/--sx/--sy` **已删除**。理由见 §11.11。

⚠️ **v0.6.0 起封面牌重新吃赛道色**：名次 / 分数 / 赛道名 / 两侧符号全用 `TRACKS[].color`
（v0.5.0~v0.5.1 因为整图是位图、吃不了色，那一版是把色撤掉的；现在回到了 v0.4.0 的口径）。

⚠️ **六张参考牌的内部版式高度不一致**（作者是 AI 直出的，不是像素级复制）：
上排的「胶囊入口」落在牌内 y≈442~462，下排落在 y≈410~430，差 32px。
v0.6.0 的**角色素材是按逐张裁剪框切的、不再受这条影响**，
但 **`art-*` 插画带仍然依赖它**，`make_card_faces.py --probe` 可以打出这张表。

### 6.2 详情页 · 发牌入场

- 点任一摞 → 路由到该赛道详情页（`/board/:id`）；六摞整体淡出，**顶牌飞到牌台中央**并放大到详情尺寸
- 详情页结构：Header → 面包屑（`返回 · 六摞牌  /  毒舌榜 · 共 12 张`，**条数动态**）→ **牌台** → 切牌进度 → Footer 规则说明
- 牌台 = 左箭头 + 大牌 + 右箭头，大牌**纵向居中**
- **默认展示第 1 张（Top1）**，此时左箭头置灰 —— 已经在第一张，没得往回翻

### 6.3 切牌

- 点 **→** 换下一张：旧牌左出、新牌右入，两段同时跑 —— 交接的时候牌台一直是满的，中间不留空档
- 第 2 张起左箭头点亮，两个方向都能翻；翻到末张时右箭头置灰
- 反向点 **←** 是同一套动画的镜像
- **三种换法完全等价**：点箭头 / 按键盘 ← → / 左右滑动（细则见 6.5）

### 6.4 ⚠️ 条数不固定，所有数字必须动态

榜单条数由当天候选决定，**1 ~ N 张都可能**，绝不能写死 3。三处涉及数字的地方：

| 位置 | 设计稿写法 | 口径 |
|---|---|---|
| 封面牌（首页） | `点击进入 · 看完整榜单` | **刻意不写数字** —— 还没进详情页，条数没有意义，也避免和详情页打架 |
| 详情页面包屑 | `毒舌榜 · 共 12 张` | 数字动态 |
| 进度文字 | `第 3 张 / 共 12 张` | 两个数字都动态；只剩 1 张时左右箭头**同时置灰** |

**缩略进度不能用固定几格**，改成**横向滚动轨道**：轨道内放 N 个缩略卡，当前项白底 + 赛道色描边 + 略微放大；
超出可视区时轨道横滚，当前项自动滚到可视区中间。
设计稿里画了 **12 张**作示例 —— 只为说明"数量可以很多"，**不是上限**。条数少时轨道自然留白，不做拉伸填充。

### 6.5 三种换法细则

| 方式 | 行为 |
|---|---|
| **点箭头** | 点哪儿走哪儿；到头的那一侧箭头置灰、不可点 |
| **键盘 ← →** | 详情页有焦点时生效；连按走多张，**不做加速**；输入框 / 文本框内不拦截；`Esc` 返回六摞牌 |
| **左右滑动** | **向左滑 = 下一张，向右滑 = 上一张**（跟手方向与牌的运动方向一致） |

滑动的三条实现细节：

1. **跟手**：拖动过程中牌直接跟随位移，**松手之前不播动画**（不要既跟手又自动走）
2. **吸附阈值**：拖动距离超过牌宽 **25%** → 判定换张，播 320ms 动画补完；未超过 → 弹回原位（160ms）
3. **拖动时箭头让位**：两个箭头淡出，避免和手指 / 光标打架；松手后按新状态恢复

### 6.6 尺寸规格

**⭐ 第一条硬规矩：所有卡牌严格按标准扑克牌比例 1 : 1.4，没有例外。**

牌背 / 封面牌 / 详情大牌 / 缩略卡 / 动画分帧里的牌**全部同一口径**。
牌是这页的视觉主体，比例一歪整摞牌立刻变成便签纸 —— 这是**不许按内容自适应高度**的地方。

> ⚠️ 曾有过两次"封面牌例外"：**v0.5.1** 让封面按参考图原比例 1:1.218（为了不裁原图），
> **v0.6.0** 改回来了 —— 封面回到自绘版式后自然也是 1:1.4，两者重新统一。
> **别再把"封面 1:1.218"当成遗留约定去维护**，那是史料，见 §11.10 / §11.11。

**牌高写死之后，长内容靠「形象区」吸收。** 封面牌与详情大牌**都成立**：
两者的**形象区高度都是 `fill_container`**，其余各段（角标行 / 标题 / 正文 / 按钮）才按内容自适应，
形象区吃掉剩下的全部高度。所以**文案加长 → 牌高不变、形象区变矮**，牌框永不被撑开。
真正的常量只有四个宽度：202 / 396 / 300 / 178。

⚠️ **封面牌的形象区只有 157 高**（见 §6.1 的预算表），比详情大牌矮得多 ——
这是刻意的：封面要的是"角色站在那儿"的剪影感，不是插画细节。素材也按这个尺寸给 2× 图（356 × 292 上限）。

**连带项（改牌高时必须一起动）**：形象区（改 `fill_container`）、
切牌屏四帧里箭头与牌的纵坐标（牌变矮后箭头要跟着重新居中）、
牌堆区的 `counterAxisAlignItems: "CENTER"`（否则摞贴顶、下方空一截）。

两屏的牌尺寸一致；浮层不是缩水版，只换 Header、面包屑、箭头和字号档位。

### 6.7 榜期切换（v0.7.0：日榜 / 周榜，从分段控件改成榜期卡）

#### 为什么旧设计是错的

v0.6.0 用的是一个 iOS 风格分段控件（`.seg` / `.seg-b`），Header 右上角就「日榜」「周榜」四个字。
量了三件事，它一件都没说：

| 问题 | 实测依据 |
|---|---|
| **不说时间范围** | 日榜 = 今天 00:00 起（`rangeStart` 用 `setHours(0,0,0,0)`）；周榜 = **7 天前这一刻**（`now − 7×DAY_MS`），**不是自然周**。用户以为「周榜」= 本周一至今。 |
| **切换代价不可见** | 日榜 `maxPages 40` / 周榜 `maxPages 45`，首次评分要翻 45 页、约 100 秒。旧设计切过去头部毫无变化，用户不知道自己在等什么。 |
| **分布差异被抹平** | 实测**嘴硬榜日榜 2 张、周榜 0 张**；阴阳榜日 2 / 周 5。点进去才看到「暂无上榜」，像出了 bug。 |

三个问题的共同点：**代价和差异都发生在「切过去之前」，而旧控件只提供「切过去」这一个动作。**

#### 四层信息，一张卡摊开

榜期卡（`.rng-card`）不再是两个可以点的字，而是一份**榜单档案**：

| 层 | 内容 | 取值 |
|---|---|---|
| 身份 | 榜期徽标 `.rng-tag` | 「日榜」/「周榜」—— **降级为身份标识**，不再承担信息量 |
| 时间窗 | `.rng-l1` | 「今天 00:00 → 现在」/「7 天前 → 现在」 |
| 规模 | `.rng-l2` | 「已扫 117 条 · 共 33 张」（+ mock 时缀「· 演示」） |
| 状态 | 卡面整体三态 | 就绪 / 评分中（`is-building`）/ 失败（`is-failed`） |

| | 站点页 | 扩展浮层 |
|---|---|---|
| 卡 | 236 × 44 | **210 × 34** |
| 徽标 | 62 × 32 | 54 × 26 |
| 下拉面板 `.rng-pop` | 460 宽，`top: 52` | **400 宽**，`top: 40` |
| 面板列宽 | `96 / 66 / 66 / 1fr` | `84 / 58 / 58 / 1fr` |

三态（⛰ 三种状态必须一眼可分，**不能只靠一行小字**）：

| 状态 | 判据 | 表现 |
|---|---|---|
| 就绪 | `status==='ready'` | 墨黑描边 + `⇄` |
| 评分中 | `status==='building'` | **蓝边 + 蓝徽标 + 蓝字** + 旋转 spinner；文案按 `progress.phase` 分「正在扫描 · N 条」/「正在评分 N/M 条」 |
| 失败 | `status==='failed'` | 灰边 + 橙字 + `!`；第二行给**旧榜时间戳**（不是「暂无数据」，因为可能真有旧数据可看） |

#### ⭐ 展开态：同赛道 · 两榜并排对照表

**这是本次改版最实质的一处。** 旧设计只让用户选「看哪一档」；新设计让他在**切换前**就看清两档差在哪。

四列：`赛道` / `日榜` / `周榜` / `差异`。六行 + 合计行 + 底部代价提示。

差异文案**分六档**（不是笼统的「暂无」）：

| 条件 | 文案 | 样式 |
|---|---|---|
| 任一侧为 `null` | 尚未生成 | `.is-pending`（半透明、**不可点**） |
| `周 0 且 日 > 0` | **周榜空榜** | `.is-empty` 暖底 `#FFF9F5` + 橙字 `#FF5A3C` |
| `日 0 且 周 > 0` | 本档空榜 | 同上 |
| `周 > 日` | 周榜多 N 张 | `.is-more` 绿字 `#12A173` |
| `日 > 周` | 本档多 N 张 | 同上 |
| 相等 | 持平 | 默认灰 |

⭐ **「空榜」是数据事实，不是加载失败。** 六条赛道互斥、每条只进最高分榜，
分布天然偏斜（spec §11.6），嘴硬榜周榜 0 张是**正常结果**。所以给它暖底 + 橙字显式点出，
而不是留一个和「尚未生成」长得一样的破折号。

合计行给两档的**张数**与**扫描量**：`合计 33 | 35 | 扫描 117 → 730 条` ——
「117 → 730」这一对是「日榜便宜、周榜贵 6 倍」最直接的证据。

底部提示行固定：`周榜需翻 45 页、约 100 秒完成首次评分`（数字来自 `/api/board/spec`，前端不写死）。

行即入口：`role="button" tabindex="0" data-range="<peer>"`，**点行 / Enter / Space 都切档**。
`is-pending` 行不带 `data-range`（点了没反应比不给入口更糟）。

#### ⭐ `peek(range)` —— 纯只读接口（本节最重要的实现约定）

展开面板要对照「对面那一档」，**但绝不能因此触发一次真评分。**
`createBoardEngine` 因此新增 `peek(range)`：**只读内存 / 磁盘缓存，绝不调 `ensure()`**。

| | `ensure(range)` | `peek(range)` |
|---|---|---|
| 有缓存 | 立即返回 | 立即返回 |
| 无缓存 | **翻 45 页 + 一两分钟 AI + 烧 token** | 返回 `null`（0.02s） |

⚠️ **`peek` 必须三处同步，漏一处就静默烧 token**（前端以为在只读，实际走 `ensure()`）：

| 位置 | 加什么 |
|---|---|
| `site/serve.mjs` `handleApiBoard` | `const peek = u.searchParams.get('peek')==='1' \|\| body?.peek===true` → 提前 `return` |
| `extension/api.mjs` `apiBoard` | 同上 |
| `extension/background.js` 路由 | **转发** `peek` 标志，否则扩展侧 `apiBoard` 收不到 |

没缓存时后端回 `{ status: 'none', boards: [] }`，前端显示「尚未生成」。
⭐ **`null` 不能当成 0 张** —— 0 会被误读成「空榜」，与「空榜」这个真实数据事实混淆。

#### ⚠️ 踩过的坑：读写用了两个不同的 key

`paintRangePop()` 读 `peerCache[S.range]`（**当前**档），`loadPeer()` 写 `peerCache[peer.id]`（**对面**档）
—— 读写两个 key，对面列永远是 `—` / 「尚未生成」，**且不抛任何异常**（静态检查全绿、接口手工验也正常）。

**key 必须统一按「档位 id」取，且是 `peer.id`。** 在途标记同理：
`busy` 原本挂在 `RANGES[].busy`（常量对象），换档会串味，改成独立的 `peerBusy = {}`。

## 七、两段动画

### A. 入场：点一摞 → 牌飞入牌台（320ms）

四帧是同一段动画的四个采样点：

| 时间 | 事件 | 细节 |
|---|---|---|
| **0ms** | 按下 | 整摞 `scale 0.97` + 下沉 4px，先给一个"被按到"的反馈，然后才开始飞 |
| **80ms** | 弹起 | 顶牌从摞里被抽出来（上抬 + 右移）；另外两张留在原地开始淡出 |
| **180ms** | 展开 | 牌飞向牌台中央，同时放大到详情尺寸 |
| **320ms** | 落位 | 居中落位（396 × 554，标准扑克比例）；其余五摞同时淡出、牌堆退场。从这一刻起可以点 **→** 切牌 |

### B. 切牌：箭头 / 键盘 / 滑动（共用一套）

四帧是同一段交互的四个采样点：

| 帧 | 事件 | 细节 |
|---|---|---|
| **1 · 静止** | 待命 | 当前牌在位；第 1 张时左箭头置灰、右箭头可用 |
| **2 · 拖动中** | 跟手 | 牌随拖动位移，**箭头淡出让位**；下一个方向从对侧露出牌边 |
| **3 · 松手 · 160ms** | 交接 | 旧牌左出、新牌右入，两段重叠着跑 —— 牌台始终不空 |
| **4 · 到位** | 落位 | 新牌归位，左箭头点亮；缩略轨道走到当前格 |

- **点箭头 / 按 ← → 跳过第 2 帧**，直接走 1 → 3 → 4
- 只有滑动会走满四帧；未超过吸附阈值时从第 2 帧弹回第 1 帧

- 缓动统一用 `cubic-bezier(0.22, 1, 0.36, 1)`（先快后慢，带轻微过冲再回弹）
- **返回上一层 = 入场动画倒放**，时长压到 240ms（收比起手要快）
- **实现口径**：牌用 `position:absolute`，靠 `transform: translate3d()` + `scale()` 驱动，
  **不要改 width/height** —— 十个元素同时改宽高会触发 layout 重排，掉帧。用 CSS 变量（`--x/--y/--s`）写关键帧。
- 切牌的出/入两段共用一条时间轴，一进一出；`prefers-reduced-motion` 下直接跳变，不播动画。

**系统状态（沿用）**
- 评分中：进度条 + `已扫描 x 条 · 筛出 48 条候选 · 打分 12/48`
- 空态：今日暂无上榜
- 失败：接口超时，保留上次结果并标「旧」，不覆盖已发布榜单

### ⭐ `char-*`（抠角色）的处理链

这是 **v0.6.0 新增的一条链**，也是整套切图里最容易走歪的一条：要的不是"把图裁小"，
而是**只留下角色本体、其余全透明**。产出必须是 RGBA。

```python
zone = card.crop(CHAR_BOX[n])                       # ① 逐张裁剪框（见下表）
zone = wipe_rects(whiten_bg(zone), RANK_WIPE[n])    # ② 推白 → 抹名次的两个角
ch   = trim(keep_main(cutout(zone), near=...))      # ③ 抠透明 → 只留主体连通域 → 裁边
ch   = ch.resize(contain 进 356x292)                # ④ 等比缩到 2× 素材尺寸
```

**① `CHAR_BOX` 必须逐张给，不能用一套统一框。** 六张角色宽度差别很大
（帮你理解：最窄的 emo 带气泡要 358 宽，最窄 body 只有 306）。上下界的实测结论是：

| 量 | 实测 | 说明 |
|---|---|---|
| 角色**腿底** | **y ≈ 275** | ⚠️ 别把土星环下缘当成腿底 —— 踩过两次，裁到 236 / 252 都把腿切了 |
| 赛道名**顶** | **y ≈ 290** | 赛道名是独立连通块，会被 `keep_main` 自动丢掉，但**框最好别框进来** |
| 最终下界 | **278** | 取两者中间，上下各留约 7px 余量 |

表格（`make_card_faces.py` 头部常量）：

```python
CHAR_BOX = {
    'c1-vicious':  (86, 28, 336, 278),   'c2-absurd':   (78, 28, 312, 278),
    'c3-passive':  (74, 28, 306, 278),   'c4-stubborn': (80, 28, 326, 278),
    'c5-blah':     (92, 28, 298, 278),   'c6-emo':      (92, 28, 358, 278),
}
```

**② `RANK_WIPE` 逐张两个矩形**（左右上角），和后面 `art-*` 那条是同一个道理：
名次行（🔥1 / 8.5）与角色头**纵向完全重叠、横向分开**，没有水平的干净缝可切，
所以只能按矩形把两个角抹掉。

**③ `cutout` 必须走"外围 flood fill"，不能用全局阈值。**
角色身上有**白色高光**（土星环、Rank 的角）和**白色纸条**，全局阈值会把内部掏空。
做法是 `NEAR_WHITE = 244`（三通道都 ≥ 此值才算背景）从四边泛洪吃完，再 `FEATHER = 0.9` 羽化边缘。

**③b `keep_main` 是这一步的关键。** 参考图里**赛道名那三个字是独立连通块**，
靠"离主体的距离 ≤ `near`"把它们自动丢掉 —— 不用再去猜"赛道名顶边在哪"（那条路量错过三次）。
- `CHAR_NEAR_DEFAULT = 12`；**`c6-emo` 单独放宽到 20**：它的「emo」对话气泡和角色间隙有 15，
  阈值 12 会把气泡丢掉（气泡是角色的一部分，丢了就不完整）。
- 贴底小块（`y1 >= h - 10` 且面积 < `floor_trim`）也丢 —— 那是硬切在脚部装饰上的碎渣。

④ `contain` 进 `CHAR_OUT_W/H = 356 × 292`（= 封面形象区 178×157 的约 2×），**必须至少一边撑满**。
`check_extension.py` 会断言这一点 + 六张**互不相同**（见 §11.11）。

### ⭐ `art-*` 那三件事，每一件都有坑

**① 必须把「名次行」抹掉，而它和角色头在纵向是重叠的。**
参考图的名次（左「🔥1」右「8.5」）在 y≈76~140，角色头顶也从 y≈76 起 ——
**没有一条水平的干净缝可切**。好在它们在**横向是分开的**（中间有空档），
所以做法是：上界切 y=28（保住触角/王冠/吊灯），下界切 y=286（标题顶边在 288~300），
再把 **y < 148 的左右两角抹白**。

⚠️ **抹白边界要逐张定，不能用统一值**：六张牌的角色宽度差很多，统一值不是切到
`c6-emo` 的头（它最窄）、就是留下 `c5-blah` 的名次数字。
⚠️ **边界必须落在空档"里"**：一旦穿过数字，会剩下左边那个「8」孤零零挂在角上，
一眼就是 bug（踩过：`c5` 的右界一度取 306，正好切在「8.5」中间）。
⚠️ `c6-emo` 的 CLEAR_Y 要单独放宽到 182：它的「emo」对话气泡和名次数字在横向重叠，
清一半会留一个被切开的半截气泡，不如整块清干净。

**② 牌面那层柔光必须推到纯白。**
参考图的牌面是**带柔光阴影的浅灰**（干净页边约 249，**顶部中间那层柔光只有 230~240**）。
封面牌保留它没问题（整张牌就是那个底色），但详情大牌的形象区坐在**纯白卡面**上，
不推白就会看见一块**边界分明**的浅灰场。`whiten_bg` 用两条规则叠：
- **近白直推**：最暗通道 ≥ 236 一律纯白。用"最暗通道"判而不是"饱和度"判 ——
  那层柔光带一点淡紫/暖色偏，饱和度不高但确实不是灰。
- **亮度软斜坡 216→230**。⚠️ `lum0` 必须低到 **216**：那层柔光实测是 **233**，
  用 230/238 只能推到 241，实拍里就是形象区一片比周围白卡面暗 14 个灰阶的浅灰（踩过）。
  216 仍然安全：角色身上的彩色饱和度远高于 `sat_max`，深灰道具（废话榜的吊灯、乌云）
  亮度在 200 以下，都不会被误推白。

**③ 顺序不能换**：先 `whiten_bg`，再 `clear_top_corners`（抹出来才是纯白、和牌面接得上），
最后 `fade_edges`。若先抹后推，抹出来的 255 会被后来的软斜坡拉回 25x，边界又显形。

## 十一、实现口径（设计 → 代码的对照，2026-09-24 落地）

设计稿到代码只有一份实现，站点与扩展共用：

| 层 | 文件 | 说明 |
|---|---|---|
| 内核（环境无关） | `site/board-core.mjs` | 赛道定义 / 抓取窗口 / 入围筛选 / 评分提示词 / 解析 / 组榜 / 任务引擎 |
| 站点接口 | `site/serve.mjs` → `/api/board`、`/api/board/spec` | 缓存放磁盘 `data/board/<rangeKey>.json` |
| 扩展接口 | `extension/api.mjs` → `apiBoard` / `apiBoardSpec` | 缓存放模块级 Map（service worker 回收即清空） |
| 页面 | `site/board.html` / `board.css` / `board.js` | 扩展由 `build_extension.py` 原样复制，**零补丁** |

### 11.1 数据流水线

抓取 → 入围 → 打分 → 组榜，四段对应第三节：

1. **抓取**：日榜 `sort_type=300`（时间序）/ 周榜 `200`（热度序），翻到跨出时间窗或页数上限
   （`RANGE_SPEC`：日 40 页 / 周 45 页）。`ctime` 非严格降序，因此**整段翻完再按时间窗过滤**。
2. **入围**（确定性、不烧 token）：正文 ≥ 12 字；热度 `log1p(digg)*0.6 + log1p(cmt)*0.4` 取 Top 48。
   **热度只决定入围，不决定名次** —— 否则退化成热帖榜。
3. **打分**：8 条/次、单飞（不并发），每条同时打 6 个赛道分；同一块最多重试 1 次。
4. **组榜**：每条只进**最高分**赛道，分数 `< 6` 不上榜，每榜最多 `PER_TRACK = 12` 张。

⚠️ **`ctime` 单位是秒（10 位），JS 时间戳是毫秒** —— 比较前必须换算（判据 `> 4e10`）。
这条不换算，抓取会「一条都扫不到」，而且不报错。

### 11.2 后台任务 + 轮询

一次全量抓取 20~45s、打分再 1~2 分钟。**不能一个 HTTP 挂三分钟**：
`/api/board` 立刻返回 `{status:'building', progress}`，前端 1300ms 轮询一次，
`status` 变 `ready` 才渲染。进度分 `scan` / `score` 两段，界面据此显示不同文案与进度条。

### 11.3 AI 配置从哪来（两端不同）

- **站点**：请求体 > 环境变量 > `.ai-config.json` > 内置默认（`resolveAiCfg`）。
- **扩展**：没有服务端配置文件，所以 `board.js` 读 localStorage 的 `juejin-boom:ai-cfg`
  （**与抽卡页同一个键**，同源共享）经 **POST 体**交上去。带配置时走 POST，token 不进 URL。

### 11.4 浮层（1440×722）的三条硬约束

1. `html.embed { --k: 1 !important }` —— 浮层本身就是 722 的设计，不参与站点那套等比缩。
2. 因此 **`embed.css` 必须排在 `board.css` 之后**（同优先级后者赢）。`check_extension.py` 会校验。
3. **不显示「怎么翻牌」那条**（设计稿 04 就没有）。722 的预算 = Header 56 + 摞 301 + Footer ≈48 + 三段留白；
   塞一条 84 的说明会把牌阵顶上去。

### 11.5 赛道符号的 viewBox 口径

六个符号**各自**按图形包围盒收紧成正方形（`board.js` 的 `SYM_VB`），不能统一 `0 0 16 16`：
六个图形在 16 格里原本差一倍（旧版火焰 6.6×9.3、太极 12.4×12.4），统一缩到 12px 后火焰只剩 5px。
数值 = `getBBox()` 实测 + 线宽/2 外扩 + 正方形 ×1.04，六个都落在「12px 盒子里实占 11.54px」。
**改了任一 path 就要重算它那一行。**

形状也对齐了设计稿：毒舌=实心水滴 / 离谱=**圈**问号 / 阴阳=圆 + 右半实心（不是太极）/
嘴硬=素盾牌（设计稿里**没有**内嵌符号）/ 废话=气泡三点 / emo=雨云。

### 11.6 实测（2026-09-24，真实 AI）

2. 等比放到 `404` 宽 → `404 × 505`（不许拉伸）

4. 补边颜色取**牌面净色**，再按首末差分做**线性外推**

**净色怎么取**：`margin_face_row()` 取某一行**左右页边距像素的中位数**（不是均值 ——
均值会被页边距里偶尔压到的一点涂鸦拉偏）。上缘取切片第 0 行、下缘取最后一行，
斜率 `slope[i] = (c_bot[i] − c_top[i]) / (newh − 1)`，逐行 `c_top + slope · d` 外推。

⚠️ **不能用「内容最外两行的均值」当补边色** —— 会压到涂鸦，补出一条彩色带（踩过）。
⚠️ **内缩描边这一步不能省**：不裁掉就补边，补出来的宽度正好把描边显成「卡中卡」双框。

#### ⭐ 插画带（`art-*`）的处理链

```python
band = card.crop((14, 28, 395-14, 286))          # BAND_TOP/BAND_BOT/LEFT_IN/RIGHT_IN
band = band.resize((760, h), Image.LANCZOS)
b = whiten_bg(band)                               # ① 先推白
b = clear_top_corners(b, ...)                     # ② 再抹名次角
b = fade_edges(b)                                 # ③ 最后上下淡出
```

**① 名次行与角色头在纵向完全重叠，无水平干净缝。**
名次（🔥1 / 8.5）在 `y≈76~140`，而 c4 的触角从 `y≈32` 起、c5 的吊灯从 `y≈30` 起、
c6 的王冠从 `y≈71` 起 —— 往上切会切头，往下切会切名次。
**解法**：量「上区列直方图」（临时脚本 `output/_ref_topzone.py`）确认名次与角色
**在横向是分开的** → 上界提到 `y=28`（c1/c2/c3 在 y28~62 之间中间区一点墨都没有，
提到 28 只是多留一条白边，不会带进杂物），再**逐张抹白 `y < CLEAR_Y` 的左右两角**。

- `CLEAR_X` 六张**逐张量**（`c1 (130,274)` / `c2 (92,268)` / `c3 (100,276)` /
  `c4 (120,294)` / `c5 (140,276)` / `c6 (108,258)`）—— 六张角色宽度差很多，
  统一值不是切到 c6 的头、就是留下 c5 的半截数字。
- ⚠️ **抹白边界必须落在空档「里」**：宁可切到名次，别留半截数字。
  c5 右界一度取 306 正好切在「8.5」中间 → 角上挂半个「8」，一眼是 bug；改成 276。
- `CLEAR_Y_DEFAULT = 148`，`c6-emo` 单独取 **182**：它的对话气泡
  （`x 264~352, y 95~170`）和名次数字横向重叠，清一半会留一个被切开的半截气泡，
  不如整块清干净。
- **定位手段**：`output/_art_clear.py` 把 `CLEAR_X/CLEAR_Y` 直接画到图上，一眼看落点。

**② `whiten_bg()` 的两条规则（阈值 216 是踩出来的）**

```python
if mn >= 236:                      # ① 近白直推：最暗通道 ≥ white_floor → 纯白
    px[x, y] = (255, 255, 255)
wl = min(1.0, (lum - 216) / (230 - 216))   # ② 亮度软斜坡 lum0=216, lum1=230
```

- 用**最暗通道**判近白，不用饱和度判 —— 那层柔光带淡紫/暖偏，饱和度判据会漏掉。
- ⚠️ **`lum0` 必须低到 216**。踩过的坑：`lum0=234` 时那层柔光（实测 **233**）
  只能推到 241，比周围纯白卡面暗 5~14 个灰阶 → 形象区显出一块边界分明的**浅灰场**
  （放大图才看得出）。`lum0=230` 也还是只推到 250。
- 216 依然安全：角色身上的彩色（角 / 皮肤 / 道具）饱和度远高于 `sat_max = 36`，
  走 `sat >= sat_max → 不动` 那条分支，不会被推白。
- 调试手段：`output/_probe_field.py` 打最暗通道直方图 + 逐行剖面。

**③ 顺序不能换：`whiten_bg` → `clear_top_corners` → `fade_edges`。**
先抹后推会让抹出来的 255 被软斜坡**拉回 25x**（看着像没抹干净）。

#### ⭐ 发牌动效：为什么必须分轴

v0.5.0 之前封面与大牌同为 1:1.4，所以 `scale(var(--s))` 单轴就能"落位严丝合缝"。
现在封面 1:1.218、大牌 1:1.4，单轴会让落位**矮 72px**。改成：

```
--s0x = 封面视觉宽 / 202   --s0y = 封面视觉高 / 246   （出发）
--sx  = 大牌视觉宽 / 202   --sy  = 大牌视觉高 / 246   （落位）
```

验算：`--sx = 396/202 = 1.9604`、`--sy = 554/246 = 2.2520` → 落位 202×1.9604 = **396.0**、
246×2.2520 = **554.0** ✓ 正好等于 `.slot` 的 396×554。
代价是飞行末段牌面被纵向拉开约 15%，但它最后 110ms 是淡出交给大牌的，观感上是"牌在展开"。

#### ⭐ 尺寸契约改成自检断言（别再靠截图反推）


#### ⭐ 抠图链为什么必须 "flood fill + 连通域"，不能全局阈值

```python
zone = card.crop(CHAR_BOX[n])                       # ① 逐张裁剪框
zone = wipe_rects(whiten_bg(zone), RANK_WIPE[n])    # ② 推白 → 抹名次两角
ch   = trim(keep_main(cutout(zone), near=...))      # ③ 抠透明 → 留主体连通域 → 裁到包围盒
ch   = ch.resize(contain 进 356x292)                # ④ 等比缩到素材尺寸
```

- **`cutout` 用外围 flood fill**（`NEAR_WHITE = 244`，三通道都 ≥ 才算背景）：
  角色身上有**白色高光**（土星环、emo 气泡）和**白色纸条**，全局阈值会把内部掏空。
- **`keep_main` 是关键一步**：参考图里**赛道名那三个字是独立连通块**，
  靠「离主体的距离 ≤ `near`」自动丢掉 —— **不用再去猜"赛道名顶边在哪"**。
  这条线路我量错过三次（`208 / 203 / 219` 全是错值）：
  ⭐ **凡是"能不能自动剥掉"的判断，优先用连通域，别用一行像素的统计特征。**
- `CHAR_NEAR_DEFAULT = 12`，**`c6-emo` 单独放宽到 20**：它的对话气泡与角色间隙有 15，
  阈值 12 会把气泡丢掉 —— **气泡是角色的一部分，丢了就不完整**。
- **坐标一定要看带刻度的图**（我是输出了带 y 刻度的对照图才读准的）：肉眼看放大图时
  我两次把「土星环下缘」当成腿底，先后裁到 236 / 252 都把腿切了。
